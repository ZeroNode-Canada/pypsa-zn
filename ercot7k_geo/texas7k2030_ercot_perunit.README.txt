WHAT IS NEW
-----------
Wind and solar availability now comes from PER-UNIT HSL in ERCOT's 60-day
disclosures, on BOTH scenarios, instead of regional series allocated to units by
capacity share:

    DA forecast   60-Day DAM disclosure   (NP3-966-ER, MIS report type 13051)
    actual        60-Day SCED disclosure  (NP3-965-ER, MIS report type 13052)

The DAM HSL is the day-ahead vintage: it IS the COP highSustainedLimit at DAM
close, an identity verified on all 32,520 resource-hours.

Coverage, measured over 671 VRE injectors x 384 periods:

    DAM forecast    257,511 / 257,664 unit-periods     100.0% of 70,447.6 MW
    SCED actual     257,664 / 257,664 unit-periods     100.0% of 70,447.6 MW

This removes the regional-allocation step, which was the project's largest
synthetic claim (85.7% of solar and 43.5% of wind capacity were assigned a
synthetic weather region).


THE RESULT
----------
Solves at $0.00 total penalty. All 221 solves Optimal.
Run 01M4GZ57Y9M4TS658BVA18FZH8, PSO 3.3.0-nightly.20261007.4c08ad2.

    cycle   solves   s/solve
    SC          26      0.40
    SCEsr        9      2.45
    WA           9      4.68
    DA           9      9.97
    RT         168      0.03

The point is NOT the system totals, which barely move. It is the error structure:

    system VRE energy        forecast -3.8%,  actual +3.1%
    aggregate fcst/act bias  ~-9%  ->  ~-2.5%
    sum|act-fcst| per unit-hour   1,871,576  ->  3,201,156 MWh   (+71%)

Regional allocation gave every unit in a weather region the same shape, so its
forecast error largely cancelled WITHIN the region. The old number was
substantially an artefact of the allocation; this one is a real unit-level
day-ahead-to-real-time availability error.

Against the committed base case, exactly ONE table differs: SCH_TMP1. All 28
others are byte-identical, including every network, fleet, cycle and reserve
table, and also SCH_ATT and SCN_INJ_MAX. Only schedule VALUES move.
